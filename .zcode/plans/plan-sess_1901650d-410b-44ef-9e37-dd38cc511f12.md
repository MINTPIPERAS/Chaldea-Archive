# Chaldea Archive：方案文档 + 可运行骨架

## 已确认决策
- **部署形态**：本地单用户、免登录，API Key 本地存储（预留加密扩展位）
- **Embedding**：文档覆盖三种运行方式（云 API / 本地 Python 加载 / Ollama）+ 可切换的 Provider 抽象；**默认实现云 API**（SiliconFlow 免费的 BAAI/bge-m3，OpenAI 兼容协议）
- **数据库**：Postgres + pgvector（Docker Compose 一键起）
- **流式方案**：HTTP POST + chunked **NDJSON** + 前端 `fetch`/`ReadableStream` 逐块解析（**不使用 SSE/EventSource**）。这是 ChatGPT 网页版与 Vercel AI SDK 的同款思路，是当今主流；WebSocket 对纯聊天场景过重，理由写入文档
- **技术栈**：FastAPI（Python 后端）+ Vue3/Vite/Pinia/ElementPlus（前端）

## 一、文档交付（Docs/）

**1. `Docs/embedding-guide.md`（重点，零基础向）**
- 原理入门：文本→向量的直观解释、cosine 相似度、维度/归一化/上下文长度/MRL 截断，配 ASCII 图示
- 模型选型对比表：bge-m3（默认推荐：568M、8192 token 上下文、dense+sparse 天然适合混合检索）、Qwen3-Embedding 0.6B/4B/8B（中文质量上限更高）、multilingual-e5-large、OpenAI text-embedding-3、Gemini Embedding；给出选型结论与升级路线
- 三种运行方式详解 + 代码示例：① 云 API（默认，SiliconFlow/OpenAI 兼容 `/v1/embeddings`）② sentence-transformers 本地加载（含国内 hf-mirror 下载加速）③ Ollama 托管；`EmbeddingProvider` 抽象设计与切换配置
- pgvector 实操：建表（vector 列 + HNSW 索引）、cosine 检索 SQL、元数据过滤、与 BM25 组合的 hybrid 检索
- 分块（Chunking）策略：300–500 token、10–15% overlap、剧情文本按「说话人/章节」结构切分、术语词典锚点、chunk 元数据 schema（doc_type/source/chapter/servant_id/pos）
- 端到端示例代码（入库 pipeline + 查询检索）与常见坑清单（换模型必须重建索引、query/passage 前缀差异、批量与限流、中英混排、维度记入元数据等）

**2. `Docs/streaming-design.md`**
- SSE / HTTP 流式 NDJSON / WebSocket 三方案对比与选型理由
- NDJSON 事件协议定义：`message_start / delta / citations / usage / error / done`，每行一个 JSON 对象
- FastAPI 实现要点：`StreamingResponse` + async generator、心跳行防超时、客户端断连检测、防缓冲响应头、异常时发 error 事件再关闭
- Vue3 实现要点：`fetch + getReader + TextDecoder`、`\n` 分帧与残帧缓冲、AbortController 实现"停止生成"、Pinia 状态机、markdown 增量渲染注意事项

**3. `Docs/architecture.md`**
- 技术栈修订表（Next.js→Vue3 栈、Supabase→FastAPI+Postgres、Vercel AI SDK→自研流式、Clerk→本地免登录、R2→本地文件）及修订原因
- 系统分层图、前后端目录结构、API 一览、BYOK 本地化设计（api_configs 表 + OpenAI 兼容协议为主 + 测试连接）、RAG 管线在 FastAPI 中的模块落位（ingest/retrieve）、修订版 MVP 路线

**4. `Docs/plan.md`**：仅小幅修订——「5. 技术选型」表更新为最终版，标注指向 architecture.md

## 二、可运行骨架

**backend/（FastAPI）**
- `app/`：main.py、config.py、db.py、models.py（api_configs / conversations / messages / documents / chunks，chunks 含 pgvector 向量列）、schemas.py
- `routers/`：chat.py（`POST /api/chat/stream` → NDJSON 流式，**内置 mock provider** 便于无 Key 自测全链路）、conversations.py（会话历史 CRUD）、settings.py（API 配置 CRUD + 测试连接）
- `services/`：llm.py（openai SDK + base_url 覆盖，流式封装）、embedding.py（Provider 抽象，默认云 API，预留本地实现）
- requirements.txt、.env.example

**frontend/（Vue3 + Vite + Pinia + ElementPlus）**
- 聊天页（会话侧栏 + 消息流 + 输入框 + 停止生成按钮）、设置页（base_url / api_key / model / 测试连接）
- `stores/` chat.js、settings.js（Pinia）；`utils/stream.js`（NDJSON 解析 + AbortController）
- markdown-it + highlight.js 渲染回复

**根目录**：docker-compose.yml（postgres + pgvector 镜像）、README.md 更新（一键启动步骤）

## 三、验收标准
1. `docker compose up -d` 起 Postgres → `uvicorn` 起后端 → `vite dev` 起前端
2. 无 Key 时用 mock provider 验证流式逐字输出与中途停止；填入真实 OpenAI 兼容 Key 后真实流式
3. 设置页可保存配置并测试连接；会话与消息落库，刷新后历史可恢复
4. 向量入库/RAG 检索属 Phase 2，骨架只备好表结构与 embedding 抽象（对应原 plan 的 Phase 0 完成）

## 运行环境
Windows + Git Bash；需要 Python 3.11+、Node 18+、Docker Desktop（Postgres 用）
